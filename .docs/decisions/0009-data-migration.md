# 0009 数据迁移

## 背景

PostgreSQL 里有用户数据，表结构要随代码的版本一起变。存储桶里的音频完全是程序从文章生成的。

## 比较过的方案

- PostgreSQL：drizzle-kit 生成的 SQL 脚本；或者独立的迁移工具（如 Atlas、dbmate）。
- 音频：格式或声音变了以后重新生成；或者保留旧音频，只给新文章用新格式。

## 决定

- PostgreSQL 用增量迁移：drizzle-kit 从表定义生成带编号的 SQL 脚本，从当前版本按顺序执行；合并后的脚本不再修改。staging 在 CD 部署时执行，生产在手动部署任务里执行，开发机和测试库在建库时执行。
- 音频不迁移，用一个重建命令重新生成，和数据库迁移一起运行。

## 理由

- 迁移脚本和 ORM 的表定义一致，不用多学一个工具。
- 音频随时能重建，不需要迁移。

## 代价

- 写错的脚本只能用新脚本来纠正。
- 重新生成全部音频要花不少 CPU。

## 何时重新考虑

出现 drizzle-kit 表达不了的变更时；或者音频生成的成本，让全部重建变得不划算时。

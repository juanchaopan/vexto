# 0016 文章朗读的声音

## 背景

文章朗读是关键功能。参考项目 lingocurrent 的 spike 比较过四个样本：

| 样本 | 引擎和声音          |
| ---- | ------------------- |
| A    | Kokoro `af_heart`   |
| B    | Kokoro `am_michael` |
| C    | Supertonic F1       |
| D    | Supertonic M1       |

项目所有者选了 Supertonic F1。压缩成 MP3 32 kbps 后，大小只有 WAV 的约 4.6%。

Supertonic 的模型是 Supertonic 3，许可证是 OpenRAIL-M：允许作为服务提供给别人使用，但要把它的使用限制写进用户要遵守的条款；其中一条是对外传播生成的内容时要说明它是机器生成的。官方仓库已经归档，不再维护。模型不输出时间戳。

## 比较过的方案

- 沿用 Supertonic F1、MP3 32 kbps；或者开新的 spike 重新比较声音。
- 朗读形式：
  - 整篇音频，可以逐句播放并高亮；
  - 只能整篇播放；
  - 点哪句读哪句。
- 说明声音由 AI 生成的方式：每个播放键旁边标注；或者只在使用条款和音频文件里说明。

## 决定

- 声音用 Supertonic 3 的 F1，单声道 MP3 32 kbps。
- 每篇文章逐句合成，按每句的长度得出时间轴，再拼成整篇音频，可以逐句播放并高亮。
- 在哪里生成见 0002 和 0017。
- 用户第一次登录时确认使用条款，条款说明声音由 AI 生成，并包含模型的使用限制；MP3 文件的 ID3 注释写明是 AI 生成的声音；条款页和账号菜单里可以打开许可证全文。播放键旁边不另加标注。

## 理由

- 项目所有者已经试听并选定了这个声音和音质。32 kbps 时一分钟的音频约 240 KB，5 GB 的存储能放约 3900 篇 5 分钟长的文章。
- 许可证要求的是遵守使用限制和对外传播时说明机器生成；条款和音频文件里的说明已经满足，手机屏幕上不再占位置。

## 代价

- Supertonic 停止维护，出了问题只能自己修。
- 逐句合成比整段合成多一些开销。
- 界面上看不到 AI 声音的提示，用户只在确认条款时读到一次。

## 何时重新考虑

Supertonic 在 Cloud Run 上跑不起来或者成本太高，或者它的许可证不允许这样用时。

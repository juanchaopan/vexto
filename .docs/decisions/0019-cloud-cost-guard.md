# 0019 Google Cloud 的费用保护

## 背景

Google Cloud 必须绑定结算账户才能用 Cloud Run、Cloud Scheduler 和 Cloud Storage，绑定后没有默认的消费上限。项目所有者要求不花钱，但 Cloud Run 平时要一直能用，只在超额时自动停。

文章合成最耗 CPU：一篇 1000 词的文章约 900 vCPU 秒。第一版 5 个订阅源、每个每天最多 2 篇、每篇最长 1000 词，如果每篇都是最长，一个月约 28 万 vCPU 秒，超过 Cloud Run 任务每月 24 万 vCPU 秒的免费额度；按实际的平均长度算则在额度以内。

## 比较过的方案

- 只限量，再加预算邮件提醒，由项目所有者手动停用结算。
- 限量，再加预算超额时自动停用结算。
- Google Cloud 免费试用（90 天后要升级或停止）。
- 文章合成的用量：按最长的文章限制配置（字数上限降到约 650 词，或者每个订阅源每天只收 1 篇）；或者收集任务按月记录实际用量，到额度的一定比例就暂停合成。

## 决定

- 限量：收集任务每次执行 2 vCPU、2 GiB 内存、最长 60 分钟、失败不自动重试，一次只运行 1 个；朗读服务和结算保护各最多 1 个实例；Artifact Registry 只保留最近两个镜像，Secret Manager 只保留当前版本。
- 文章合成按月记账：收集任务记录本月（UTC 日历月）文章合成的运行时间，折算成 vCPU 秒和 GiB 秒，任何一项到 Cloud Run 任务免费额度的 80% 就不再开始合成新文章，已收集的文章等到下个月再合成。订阅源配置的校验按配置里的平均文章长度估算每月用量，超过同一个 80% 就失败。
- 预算：费用一旦大于 0，就给项目所有者发邮件，并通过 Pub/Sub 通知结算保护（一个 Cloud Run 服务，和收集任务同一个镜像），由它停用项目的结算。
- 手动停用的位置写在 `.docs/architecture.md`：Google Cloud 控制台 → 结算 → 我的项目 → `vexto-staging` 那一行的「⋮」→ 停用结算。

## 理由

- 正常使用全部在免费额度以内，平时 Cloud Run 一直正常运行。
- 按月记账让长文章也能收，又不会因为某个月文章偏长而触发结算保护、连单词读音一起停掉。
- 剩下的 20% 留给不合成文章的执行（约 10%，见 0018），以及收集任务自己测的时间和 Google 计费之间的出入。
- 一旦产生费用就自动停，不用等项目所有者看到邮件。

## 代价

- 文章特别长的月份，月底可能有几天没有新文章。
- Google 的费用数据有几小时延迟，最多可能产生几美分。
- 停用结算以后，Cloud Run、Cloud Scheduler 和模型存储桶都会停下来，新文章和单词读音不再生成，要项目所有者手动重新关联结算账户。
- 多了一个要维护的小服务。

## 何时重新考虑

愿意为更多文章或更快的读音付费时。

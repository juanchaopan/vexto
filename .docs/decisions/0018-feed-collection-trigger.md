# 0018 订阅源收集的触发

## 背景

配置文件里每个订阅源有自己的时区和每天收集的时间点，一天可能有好几个。需要有东西定时检查哪些源到点了。收集、整理和文章朗读都在 Cloud Run 任务里（见 0017）。

## 比较过的方案

- Google Cloud Scheduler 定时启动 Cloud Run 任务。
- Vercel Schedules（beta，Hobby 每次最多 15 分钟的随机延迟）触发 Web 应用收集，再让 Cloud Run 合成。
- GitHub Actions 定时任务（高峰时会延迟或被丢掉，仓库 60 天没有活动会被停用）。
- Vercel Cron（Hobby 每天最多一次）。

## 决定

- Cloud Scheduler 每 15 分钟启动一次 Cloud Run 任务 `vexto-collect`，用自己的服务账号调用，不需要 `CRON_SECRET`。
- 任务找出到点的订阅源，收集、整理、合成并发布；没有到点的订阅源时尽快退出，不加载模型。

## 理由

- Cloud Scheduler 准时，每个结算账户 3 个任务免费，这里只用 1 个。
- 整条流水线在一个地方，Web 应用只负责读。

## 代价

- 实际收集时间最多比配置的时间点晚 15 分钟。
- 没有到点的订阅源时也要启动，一个月大约用掉任务免费额度的 10%。

## 何时重新考虑

需要比 15 分钟更准的收集时间时；空跑占的免费额度太多时。

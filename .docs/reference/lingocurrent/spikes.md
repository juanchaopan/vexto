## 朗读（TTS）

**问题**：文章用哪个声音朗读，音频能压缩到多小。

**试验**：在 Windows 本机，用同一段三句话的文字（含“$12.50”和“4:45 p.m.”）生成无压缩的单声道 16 位 WAV。

| 样本 | 引擎和声音                                  | 时长               | 大小        | 加载模型 | 合成用时 | 进程 CPU 时间 |
| ---- | ------------------------------------------- | ------------------ | ----------- | -------- | -------- | ------------- |
| A    | Kokoro ONNX 0.6.1 INT8，`af_heart`          | 17.55 秒，24 kHz   | 842,442 B   | 6.1 秒   | 101.0 秒 | 599 秒        |
| B    | Kokoro ONNX 0.6.1 INT8，`am_michael`        | 19.57 秒           | 939,500 B   | 6.1 秒   | 102.3 秒 | 649 秒        |
| C    | Supertonic 1.3.1（Supertonic 3 权重），`F1` | 17.41 秒，44.1 kHz | 1,536,044 B | 3.9 秒   | 12.75 秒 | 39.3 秒       |
| D    | Supertonic 1.3.1，`M1`                      | 17.48 秒           | 1,542,188 B | 3.9 秒   | 14.2 秒  | 41.2 秒       |

压缩（ffmpeg 8.0 libmp3lame，单声道，保持 44.1 kHz）：

| 版本        | 大小        | 缩小   |
| ----------- | ----------- | ------ |
| 原始 WAV    | 1,536,044 B | —      |
| MP3 32 kbps | 70,025 B    | 95.44% |
| MP3 48 kbps | 104,925 B   | 93.17% |

**结论**：2026-11-17 项目所有者选了样本 C（Supertonic F1）和 MP3 32 kbps。

**没有验证的部分**：

- 没有部署到 Vercel，也没有在云上测过。
- 准备好的云端探测程序根本不支持 Supertonic。
- Supertonic 的权重有 398 MB，加上 onnxruntime 和 numpy，很可能超过 Vercel Python 函数 500 MB 的包大小上限。
- 按本机数据，每秒音频约耗 2.26 秒 CPU，一篇 5 分钟的文章约 720 秒 CPU；Hobby 每月只有 4 小时（14,400 秒）活跃 CPU，只够约 20 篇。
- Supertonic 的仓库已经归档、停止维护，许可证是 OpenRAIL-M。

## Speak（语音判定）

**问题**：能不能在 Vercel 上用本地引擎判定用户读得对不对，并和 OpenAI 的原始音频方案比较。

**准备**：首选 Vosk `vosk-model-en-us-0.22-lgraph`，备选 `vosk-model-small-en-us-0.15`，取前 5 个候选结果；做了一个本地录音实验页，分别统计取前 1、3、5 个结果时的判定效果。通过标准是：10 条读对的录音至少接受 9 条，10 条读错的至少拒绝 9 条，无效录音一条都不接受。

**结果**：项目所有者还没录音，只用合成的麦克风输入测过；没有 Hobby 上的测量，没有选定取几个候选结果，也没有和 OpenAI 比较。**没有结论。**

- 没有确定来源清单，也没有定时区、收集时间和每次收集篇数。

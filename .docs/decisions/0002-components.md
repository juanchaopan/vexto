# 0002 组件

## 背景

抓取网页、调用 AI、语音合成和语音判定都必须放在服务端。项目一个人维护。参考项目 lingocurrent 用的是一个 Next.js 应用加 Neon 的方案。

## 比较过的方案

- 一个 TypeScript 全栈应用，或者前端和后端分开成两个应用。
- 数据库用 PostgreSQL，或者 SQLite 系（如 Turso）。
- 文章用定时任务提前抓好，或者在用户打开时再抓。

## 决定

- 一个 Next.js 全栈应用，里面包括页面、接口和定时任务接口。
- PostgreSQL（Neon）。
- 文件放在 Neon 对象存储。
- 文章由定时任务提前收集。
- 文章朗读生成和 Speak 判定这两个组件，等 spike 有了结论再定。

## 理由

- 只有一份代码、一个部署目标，最适合一个人维护。
- PostgreSQL 最通用，托管选择多，本机用容器就能跑。
- 文章提前收集好，打开时快；原网站出了问题也不影响阅读。

## 代价

- 一个应用的边界要靠架构规则来守。
- 定时任务要依赖托管平台的定时调用：Vercel Hobby 的 cron 每天最多一次。

## 何时重新考虑

朗读或 Speak 的 spike 有结论时；收集频率需要超过托管平台的限制时。

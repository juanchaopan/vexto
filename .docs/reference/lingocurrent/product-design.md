# lingocurrent 分析：产品设计、数据和功能

main 上没有任何产品功能，也没有任何表。下面写的是它定稿的设计；实现状态单独标出。

## 功能和实现状态

| 功能 | 设计 | 实现 |
|---|---|---|
| 登录 | Clerk 受邀 Google 登录；每次请求都检查 `members` 表里的记录；访问别人的数据返回 404 | main：只装了包。草稿 PR #12：Clerk 中间件、成员检查、`/api/v1/me` |
| RSS 收集 | 每个频道有自己的 IANA 时区和每天几个收集时间点；建任务和推进下次运行时间放在同一个事务里；按文章记录检查点；最多补跑 4 次错过的时间点；只收全文 RSS，不抓网页；限制请求大小，防 SSRF | 没做 |
| 正文整理 | 规范正文：句子之间一个空格，段落之间两个换行；精确记录每句话在正文里的起止位置；HTML 绝不执行 | 没做 |
| 文章列表、搜索、阅读、播放 | 一个列表，带“上次访问”；按表头排序和筛选；英文全文检索（输入不超过 200 字符）；列表快照保留 15 分钟；鼠标翻页、触屏“加载更多”；每句话有播放键；播放器只在阅读页，0.75 到 2 倍速；跨页“全部播放”队列 | 草稿 PR #12：列表、阅读页、访问记录、私有音频地址 |
| 查词 | 点选或拖选，可以跨行跨句；选区辅助弹层；每个用户有自己的缓存；弹层可以嵌套，Esc 一次关一层 | 没做 |
| 生词本 | 原子保存（同时生成 4 个选项和 3 行进度）；同一义项重复保存时询问是否替换，保留进度；7 列表格；全部 / 新 / 进行中 / 已归档 四个标签；一次批量删除 1 到 100 张，全成功或全不做 | 没做 |
| 复习 | 见下文 | 没做 |
| 朗读和单词、例句音频 | 按 spike 结论；例句和单词音频按需生成，通过任务表去重 | 没做；spike 选了 Supertonic F1 |
| 用量记录 | 每次调用外部服务前先写一条 pending 记录；用量未知就留空，不当作 0；没有费用看板 | 没做 |

## 复习算法

每道题现场挑选：最早到期的卡片优先，没有到期的就按加入顺序出新卡。没有学习会话的概念，也没有每日上限。

| 事件 | 效果 |
|---|---|
| 答对 | 轮次加 1，按新轮次等待：第 1 到 6 轮分别是 1、2、4、7、15、30 天 |
| 到第 7 轮 | 这种模式完成，不再安排 |
| 答错 | 轮次减 1（最低 0），10 分钟后再出 |
| 技术失败、没提交、结果未知 | 不变 |
| 提交未到期或已完成的卡 | 409 |
| 24 小时内用同一个操作 ID 重试 | 返回“已保存”，不重复写入 |

- 一天按 24 小时整算。
- Spell 判定：NFC 规范化、去首尾空格、合并连续空格、不区分大小写，然后和可接受的词形做精确比较，不算编辑距离。
- Translate：4 个选项，正确选项的 ID 不发给浏览器。
- Speak 和 Spell 的题面不包含词条本身、可接受词形和音频地址。

## 数据模型

约定：主键用 UUID；时间用 `timestamptz`，存 UTC；约束同时用 Zod 和 SQL CHECK 表达；每张表归一个模块所有。

**身份、来源和文章**

| 表 | 主要字段和约束 |
|---|---|
| `members` | Clerk 用户 ID（唯一）、状态（active / revoked） |
| `sources` | 名称、允许的源站、图标、条款审核时间、是否启用（审核过条款才能启用） |
| `source_icons` | 图片字节（bytea）、类型、大小、校验和；只收 PNG 或 WebP，不超过 64 KiB |
| `channels` | 来源、名称、feed 地址（唯一）、分类、时区、是否启用 |
| `channel_schedules` | 频道、本地时间、目标篇数、下次运行时间；同一频道同一时间唯一 |
| `source_items` | 来源、外部标识的哈希（同一来源内唯一）、首次看到的时间、对应文章；文章被淘汰后这条记录保留，防止重复收集 |
| `articles` | 频道、原文地址、标题、收集和发布时间、正文、正文哈希、状态（preparing / ready）、当前音频；英文全文检索列加 GIN 索引 |
| `article_sentences` | 文章、句序号、段序号、句子文本、在正文里的起止位置、音频起止毫秒 |
| `visits` | 用户、文章、首次和最近打开时间 |

**查词和生词本**

| 表 | 主要字段和约束 |
|---|---|
| `lookup_entries` | 用户、上下文句子和它的哈希、选区起止、选中的文字、词条（lemma）、词性、义项键、中文释义、可接受的词形；同一用户、同一句子、同一选区唯一，这就是查词缓存的键，不同文章里的同一句话可以共用 |
| `examples` | 查词结果、例句文本、目标词在例句里的位置、内容哈希 |
| `vocabulary_cards` | 用户、词条、词性、义项键、中文释义、可接受的词形、原句和选区；同一用户、同一词条、词性和义项唯一 |
| `vocabulary_examples` | 卡片自己的例句，保存时从查词缓存复制过来，删卡时一起删 |
| `translation_sets` | 卡片、4 个选项、正确选项 |

目标位置都用 UTF-16 的左闭右开区间，不能切开代理对。

**复习**：`review_progress` 以（用户、卡片、模式）为主键，字段有轮次、到期时间、最近一次作答时间；只有轮次为 0 或已完成时，到期时间才能为空。

**临时数据**：播放队列和它的条目（约保留 24 小时）、列表快照和它的条目（约保留 15 分钟）。

**任务、媒体、用量和去重**

| 表 | 用途 |
|---|---|
| `pending_jobs` | 后台任务：种类（收集频道、文章朗读、例句朗读、单词朗读）、去重键、负载、状态、尝试次数、重试时间、租约到期时间、fence 令牌、检查点；成功就删除，没有“已完成”状态 |
| `pending_job_items` | 一次收集任务里的每篇文章 |
| `media_assets` | 对象键、对象版本、大小、时长、状态（staging / ready / retiring）、重试信息 |
| `media_references` | 谁在用哪个音频，缓存键唯一 |
| `storage_scope` / `storage_reservations` | 存储容量和预留，靠行锁防止超额 |
| `usage_operations` / `usage_attempts` | 每次外部调用：服务商、模型、请求 ID、状态、输入和输出 token、音频秒数、估算费用和价格版本 |
| `mutation_receipts` | 按操作 ID 去重，保留 24 小时 |

**删除规则**：淘汰一篇文章的音频时，在一个事务里删掉文章、句子、访问记录、队列条目和只属于它的引用，把音频标记为 retiring，事务提交后再删对象并重试。删卡时一起删它的选项、三行进度和例句，查词缓存保留。

## AI 的用法（设计）

- 服务商 OpenAI，服务端直接调用；查词模型没有具体定，只写了“满足质量的低价模型”。
- 设计了这些接口：
  - 词形还原：把选区还原成词条和词性。
  - 上下文解释：带上用户已有的义项，能复用就复用，不能就新建；返回中文释义、带目标位置的例句和可接受的词形。
  - 为固定义项生成新例句。
  - 生成 4 个互不相同的选项，其中 1 个正确，只在保存时生成。
  - 文章、例句和单词朗读；语音判定。
- AI 返回的结果先用 Zod 校验格式，再做语义校验：目标位置的文字对得上、词形变化合理、正确选项恰好一个。
- 文章内容只当数据，里面的指令一律忽略；不给模型任何工具。
- 刷新和保存都由用户明确触发，自动重新获取数据不会调用 AI。
- 交互式调用最多重试一次临时错误，外加一次修复尝试。
- 不设每个用户的配额，也没有费用超限时的自动停止。估算的用量是每月 3 万次查词、3 万次 Speak。

## 存储的用法（设计）

- 音频放在 Neon 私有存储桶，用 S3 协议访问（必须开 path-style）。对象不可变，并且有版本。
- 播放时用预签名地址，约 10 分钟有效，过期重新签；支持 Range 请求；音频不经过函数转发。
- 容量快满时按创建时间删最早的音频：到 95% 开始，删到 90% 以下为止，每批最多 50 个。
- 来源图标存在 PostgreSQL 里；Speak 的原始录音不保存。
- 本地开发用 Adobe S3Mock 代替对象存储，它不校验预签名的签名。

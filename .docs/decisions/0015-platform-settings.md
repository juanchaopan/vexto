# 0015 平台设置和密钥

## 背景

- 公开仓库在 GitHub 的任何套餐下都强制执行分支规则和必过检查，也支持按环境保存密钥。
- 本 issue 只搭建 staging。

## 比较过的方案

- 分支规则：按工作流的标准设置；或者同样的规则，但允许项目所有者绕过。
- 远程 issue 分支：永久保留；或者合并后删除。
- App：只装 Renovate；或者再装 Claude GitHub App。

## 决定

- main 用规则集保护：
  - 必须走 PR；
  - 必过检查全部通过，并且分支和 main 同步；
  - 必须解决所有评审对话；
  - 只允许 squash 合并；
  - 禁止强推和删除；
  - 没有旁路用户。
- 远程 issue 分支永久保留。
- 打开密钥扫描、推送保护和 Dependabot 漏洞提醒。
- 只装 Mend Renovate App。
- 本 issue 只设置 GitHub 环境 `staging` 的三项：密钥 `VERCEL_TOKEN`（项目所有者新建的令牌，只给 staging 用），变量 `VERCEL_ORG_ID` 和 `VERCEL_PROJECT_ID`。其余密钥由用到它们的功能 issue 设置。

## 理由

- 规则由平台强制执行，网站上的操作也绕不过去。
- 保留分支，留下每个步骤的提交记录。
- 密钥按环境分开，staging 的令牌不能用来部署生产。

## 代价

- 紧急情况下也只能走 PR。
- 令牌到期前要换新的。

## 何时重新考虑

有了其他贡献者，或者搭建生产环境时。

# 0001 指标

## 背景

项目简介定下的用户是项目所有者和身边少数几个人，只用手机网页，一个人业余维护，费用由项目所有者承担。

## 比较过的方案

- 基本指标：规模、可用性、一致性、成本、维护能力，按简介推出。也比较过更大的规模和更高的可用性。
- 性能：查词 3 秒内开始出现解释、文章页 LCP 2.5 秒；只要查词速度；不设。
- 资源：不设；限制首屏 JavaScript 不超过 200 KB。
- 安全：一组基本安全要求；不设。
- 可访问性：不设；WCAG 2.2 AA 的自动检查。
- 兼容性：iOS Safari 和 Android Chrome；只保证 Chrome；不设。

## 决定

- 规模不超过约 10 个账号；可用性尽力而为；数据只存在一个 PostgreSQL 里，读到的都是最新写入的数据；托管用免费额度；一个人维护。
- 兼容性：iOS Safari 和 Android Chrome 的最近两个大版本，手机尺寸。
- 不设性能、资源、安全和可访问性指标。

## 理由

用户很少、都是熟人，可用性和性能不需要承诺。兼容性要设，因为用户用的是 iPhone 和安卓手机。

## 代价

- 没有性能指标，就不做性能测试；页面变慢只能靠人发现。
- 没有安全指标；登录、权限和数据隔离仍然由安全测试用例覆盖。

## 何时重新考虑

用户明显增多、开放给熟人以外的人，或者出现明显的性能问题时。

# 0019 Google Cloud 的费用保护

## 背景

Google Cloud 必须绑定结算账户才能用 Cloud Run、Cloud Scheduler 和 Cloud Storage，绑定后没有默认的消费上限。项目所有者要求不花钱，但 Cloud Run 平时要一直能用，只在超额时自动停。

## 比较过的方案

- 只限量，再加预算邮件提醒，由项目所有者手动停用结算。
- 限量，再加预算超额时自动停用结算。
- Google Cloud 免费试用（90 天后要升级或停止）。

## 决定

- 限量：朗读服务和结算保护各最多 1 个实例，收集任务一次只运行 1 个，订阅源配置合计每天不超过约 10 篇文章，Artifact Registry 只保留最近两个镜像，Secret Manager 只保留当前版本。
- 预算：费用一旦大于 0，就给项目所有者发邮件，并通过 Pub/Sub 通知结算保护（一个 Cloud Run 服务，和收集任务同一个镜像），由它停用项目的结算。
- 手动停用的位置写在 `.docs/architecture.md`：Google Cloud 控制台 → 结算 → 我的项目 → `vexto-staging` 那一行的「⋮」→ 停用结算。

## 理由

- 正常使用全部在免费额度以内，平时 Cloud Run 一直正常运行。
- 一旦产生费用就自动停，不用等项目所有者看到邮件。

## 代价

- Google 的费用数据有几小时延迟，最多可能产生几美分。
- 停用结算以后，Cloud Run、Cloud Scheduler 和模型存储桶都会停下来，新文章和单词读音不再生成，要项目所有者手动重新关联结算账户。
- 多了一个要维护的小服务。

## 何时重新考虑

愿意为更多文章或更快的读音付费时。

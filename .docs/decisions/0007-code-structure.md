# 0007 代码结构

## 背景

一个 Next.js 应用里会有阅读、查词、生词本、复习、收集、朗读等多个功能。

## 比较过的方案

- 结构：按功能分模块、模块内再分层；或者按技术类型分目录。
- 测试：按层规定测试类型；或者不按层规定。
- 命名：全部小写加连字符；或者组件文件用 PascalCase。

## 决定

- `src/app/` 只放路由和页面入口；`src/features/<功能>/` 下分 `domain`、`server`、`ui` 三层，对外只通过 `index.ts`；`src/lib/` 放共用代码。
- 依赖方向是 app → features → lib。`domain` 不依赖框架和外部服务，不允许循环依赖。这些规则由 dependency-cruiser 检查。
- 每层的测试：`domain` 写单元测试，`server` 写用真实数据库的集成测试，有交互的 `ui` 写组件测试，页面流程写端到端测试。测试文件放在被测文件旁边。
- 文件名全部小写加连字符。

## 理由

- 一个功能的代码都在一处。
- 业务规则能单独测试。
- 小写文件名在 Windows 和 Linux 之间不会因为大小写出问题。

## 代价

- 跨功能复用要先想清楚放在哪里。
- 规则多，新代码要照着写。

## 何时重新考虑

功能多到一个模块难以管理，或者规则频繁被迫例外时。

# lingocurrent 分析：差异、缺陷和薄弱点

实现被当作意图的证据来看，而不是意图本身。下面列出文档和实现对不上的地方、实现里的缺陷，以及设计上的风险。

## 文档已经过时，或者互相矛盾

1. README 和部署文档还写着“没有创建任何云资源”“两个 Vercel 项目都没部署过”。实际上 2026-11-17 已经部署过 staging，现在还在线。
2. README 还在让人“下一步运行 /roadmap”，但路线图早就做完了；架构概览说 docker compose 文件“还没生成”，但它已经存在。
3. 环境搭建指南说 `VERCEL_TOKEN` 是环境级密钥，还让建 `preview` 环境。实际上它是仓库级密钥，`preview` 环境也不存在，所以两个预览工作流都跑不起来。指南写的初始值 `DEPLOY_ENABLED=false` 也和现在的值（true）不一样。
4. 设计和架构文档里有好几处自相矛盾：
   - 任务表归 content 模块，但 media 模块也要用；去重回执表写的是“由各个用例的模块所有”。这两点和“模块互相隔离”的规则冲突。
   - 模块表还写着 review 模块拥有“答题记录”，和无会话复习的设计冲突。
   - 验证文档还在引用旧的需求范围、“四张表”和已经删掉的历史页面。
   - 状态机文档说“一天按 24 小时整算”还没定，其他文档说已经采纳。
   - 批量删除的上限一处写“1 到 100”，一处写“100”。
   - 原型和规格里的侧栏宽度、每页条数对不上。
5. 很多文档在开头加了“2026-11-16 最终版”的说明来推翻下面的旧内容，读起来很费劲。
6. 主分支上的决策记录 0016 还写着“先用 OpenAI 做质量参照”，spike 分支上已经改成“先用免费声音，OpenAI 只做备选”，但这个改动只在 spike 分支上。

## 实现里的缺陷

1. **AI 评审从来没有真正运行过**：没有配 Claude 凭据，评审任务一直被跳过。实际起作用的门槛只有 `risk-gate`、`ci` 和 `commit-lint`。
2. **密钥出现在命令行参数里**：部署脚本用 `--env KEY=value` 和 `--build-env` 把密钥传给 Vercel CLI，日志里会被遮住，但在运行机的进程列表里看得到；服务端密钥也被放进了构建环境，范围比需要的大。spike 的探测程序对 `OPENAI_API_KEY` 也是这样传的。
3. **部署时传入的环境变量不全**：`CRON_SECRET` 和 `AI_BASE_URL` 没有传，`SCHEDULE_ENABLED` 写死为 `'false'`。
4. **部署后没有冒烟测试**：部署工作流不访问部署好的 `/api/health`。
5. `commit-lint` 在 merge queue 里什么都不检查（不过也没开 merge queue）。
6. `@claude` 工作流的注释说推送到 `feature/` 分支，实际配置是 `codex/`。
7. 开 PR 的命令用 `npx jscpd .`，没有用仓库自己的 `pnpm duplication`；CLAUDE.md 提到的 `/spike` 命令不存在。
8. Tracing 没有设采样率，决策记录 0014 要求低采样率；有流量后可能用完 Hobby 每月的额度。
9. 装了好几个没用到的依赖；架构规则允许的启动装配文件不存在；规则里列了没安装的 `openai`；`.env.example` 缺 `AI_BASE_URL` 和预览要用的 `NEON_*`。
10. Dependabot 和 Renovate 同时开着；Renovate 的初始化 PR 过不了仓库自己的检查。
11. 仓库主页地址写错了，访问返回 404。
12. 欢迎页自己渲染了 `<main>`，全局 CSS 又直接给 `main`、`h1`、`p` 加了样式；截图测试依赖 Linux 容器里的字体，却还提交了一份 Windows 的基线。
13. 没有 CodeQL，没有依赖漏洞检查，也没有许可证文件。

## 过程上的问题

1. 代理做了超出 issue 范围的事：#6 只要环境，结果写出了 74 个文件的业务骨架（草稿 PR #12），只好留着不合并。
2. 生产 Clerk 实例的邀请邮件被 Gmail 拒收，问题还没解决。
3. 两个 Clerk 实例共用一个 Google OAuth 客户端，违反 Google 的规定。

## 免费套餐下的风险（它自己的文档也承认）

1. 每月 3 万次 Speak 判定，平均每次只有约 0.48 秒 CPU。
2. Neon 每月 5 GB 的出口流量由数据库和音频共用。
3. 1 GB 的数据库会被永不删除的个人数据慢慢占满。
4. Vercel Schedules 每个团队每个周期最多 5000 次运行。
5. 文章朗读在 Vercel Hobby 上的 CPU 预算明显不够（见 `spikes.md`）。

## 对 vexto 的提醒

- 不要照搬密钥的传法：密钥直接存在 Vercel 项目的环境变量里，或者通过标准输入设置，不要放进命令行参数。
- 部署后要跑冒烟测试。
- AI 评审要配上凭据；被跳过不能当成通过。
- 依赖更新只用一个工具。
- 每个 issue 只做它范围内的事。
- 文档只保留最新内容，过时的部分直接删掉，不要用“最终版”说明来覆盖旧文字。

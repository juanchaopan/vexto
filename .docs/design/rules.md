# 规则

这份文件写界面之外的规则：谁能用、数据怎样隔离、订阅源和收集流水线、朗读和存储、AI 查词、生词本、间隔复习、并发、错误、通知和用量记录。界面上怎样表现见 `screens.md`，表结构见 `data.md`，接口的路径、字段和错误代码见 `interfaces.md`。

## 成员和登录

- 只有受邀的人能用。名单以每个目标数据库的 `members` 表为准，项目所有者用 `task member -- add|revoke|list <邮箱> --target <环境>` 管理；命令按 `.docs/architecture.md` 的做法用 Neon CLI 取得目标数据库的连接地址。
- 邮箱存成小写，比对不分大小写。
- `add`：邮箱不在表里时建一行 `active`；已有 `revoked` 的行时把它设回 `active`；已经是 `active` 时不改动，只提示。`list` 按加入时间列出每行的邮箱、状态、是否已绑定 Clerk 用户和确认过的条款版本。
- 登录用 Clerk 的 Google 登录，Clerk 不限制注册：任何人都能完成 Google 登录，但只有已验证邮箱属于 `active` 成员的人能用，其余的人看到没有资格页。
- 绑定：用户登录后的第一个请求，按 Clerk 里已验证的邮箱找到 `active` 且 `clerk_user_id` 为空的行，写入这个 Clerk 用户 ID。已经绑定的行只认绑定的那个 Clerk 用户；换 Google 账号要先 `revoke` 再 `add`。
- 每个请求都按 Clerk 用户 ID 查一次 `members`：没登录返回 401；不是 `active` 成员返回 403；客户端传来的用户 ID 不作为授权依据。登录页、许可证页 `/license` 和健康检查 `/api/health` 是公开的，不检查成员和条款。
- 退出登录用 Clerk，同时清空浏览器里所有缓存的个人数据和音频；播放速度是设备的设置，保留。

## 使用条款

- 登录后，用户确认过的条款版本不是当前版本时，所有页面都显示全屏条款页；除了读取自己的资料和确认条款，所有接口都返回 403 `TERMS_REQUIRED`。
- 条款全文、版本号放在哪里、什么时候升版本，见 `terms.md`。

## 权限和数据隔离

- 访问记录、查词结果、生词本、复习进度和去重回执都属于一个用户，每个查询都按当前用户过滤。
- 访问不存在的资源或别人的资源，一律返回 404，不区分两者。
- 子表（例句、Translate 选项）不存所有者，读写时连接父行校验。
- 文章、文章音频、单词和例句的音频是共用的：所有成员看到同样的文章，同一段文字的读音只合成一次。
- 没有管理员界面；用量只记录，不展示。

## 取消资格

- `task member -- revoke` 在一个事务里：把成员设为 `revoked`，清空 `clerk_user_id` 和条款确认记录，删除这个人的生词本（词卡、例句、选项、复习进度）、查词结果、访问记录和去重回执；用量记录保留，`owner_id` 置空。
- 取消后，这个人的下一个请求就返回 403。
- 删除的数据不能恢复；重新加回名单的人重新绑定 Clerk 用户，从空的生词本开始，并要重新确认条款。

## 收集流水线

收集、整理和文章朗读都在 Cloud Run 任务 `vexto-collect` 里完成，Web 应用不收集，也不合成文章。任务的启动方式和资源见 `interfaces.md`。

### 防止重叠的租约

- `job_leases` 表里有收集任务的一行（迁移时建好）。每次执行开始时用一条原子的 UPDATE 取租约：只有这一行的 `expires_at` 已经过去时，才写入本次执行的 ID 和 `now() + 70 分钟`；更新到一行就拿到了租约，没更新到就立刻退出。用连接池地址 `DATABASE_URL`，不用会话级的锁，不需要另外的密钥。
- 租约 70 分钟，比任务的超时（60 分钟，Cloud Run 到时终止任务）长，所以执行期间不续期。一次执行开始 45 分钟后不再开始新的合成，已经写入的 `preparing` 文章由下一次执行合成；最长的文章（1000 词，约 900 vCPU 秒，2 vCPU 上约 7.5 分钟）在第 45 分钟开始也能在超时前合成完。
- 执行结束时（包括失败退出前），把本次执行持有的租约设为立刻到期。进程崩溃或被终止时，租约到时自动失效。

### 合成预算

文章合成按月记账，月份按 UTC 算。每月预算是免费额度乘预算比例：vCPU `240000 × 0.8 = 192000` vCPU 秒，内存 `450000 × 0.8 = 360000` GiB 秒。剩下的 20% 留给两件事：不合成文章的执行（每 15 分钟一次的空跑、收集和整理，约占免费额度的 10%，见决策 0018），以及收集任务自己测的时间和 Google 计费之间的出入（见决策 0019）。

- 记账：每次合成文章（成功或失败）结束时，把这次合成的运行秒数加进 `synthesis_cpu_months` 里当月的那一行。当月用量是 `运行秒数 × vCPU 数`（vCPU 秒）和 `运行秒数 × 内存 GiB`（GiB 秒）。进程被终止时，那次没记上的部分不计。
- 预算用完：合成一篇文章之前，当月的 vCPU 秒或 GiB 秒任何一项已经达到预算时不开始合成。文章留在 `preparing`，`attempts` 不加，`retry_at` 设为下个 UTC 月的第一刻，到时接着合成；这不算失败。收集照常进行，新收的文章也这样等到下个月。
- 配置校验按平均长度估算：每日字数 `W = Σ（每次篇数 × 每天时间点数 × 规划用的平均字数）`，对所有启用的订阅源求和。按每分钟朗读 150 词、一篇 5 分钟的文章约 680 vCPU 秒（每分钟音频 136 vCPU 秒），每月 vCPU 秒估算为 `C = W ÷ 150 × 136 × 31`，每月 GiB 秒估算为 `C ÷ vCPU 数 × 内存 GiB`；任何一项超过预算时校验失败。第一版 `W = 5 × 2 × 600 = 6000`，`C` 约 168640 vCPU 秒，GiB 秒也约 168640。

### 调度

- 每个订阅源的收集时间点按它的时区算出当地时间，存 UTC。夏令时跳过的时刻顺延到当天第一个有效时刻；重复的时刻只跑第一次。
- `feed_cursors.last_occurrence_at` 记着每个订阅源处理完的最后一个时间点。执行时，对每个启用的订阅源处理 `(last_occurrence_at, 现在]` 之间到点的时间点，从早到晚，一次最多 4 个，更早的放弃；处理完一个就推进游标。
- 新加的订阅源没有游标：第一次执行时把游标设为现在之前最近的那个时间点，从下一个时间点开始收集，不补以前的文章。
- 读订阅源失败（网络错误、超时、非 2xx 响应、解析不了）时不推进游标，`failed_attempts` 加 1，按下面“失败和重试”的退避设 `retry_at`，到时再读；第 5 次仍失败就放弃这个时间点，推进游标，清零，写日志。
- 没有到点的订阅源、也没有到时间的 `preparing` 文章时，任务尽快退出，不加载朗读模型。

### 一次执行的顺序

1. 取租约，拿不到就退出。
2. 处理 `preparing` 且 `retry_at` 已到的文章，合成。
3. 处理到点的时间点，收集新文章并合成。
4. 删除过期的行（见“保留期限”）。
5. 释放租约。

每篇文章合成之前先检查合成预算和存储容量，存储需要时淘汰旧音频（见“朗读和存储上限”）。

### 选条目

- 读到订阅源后给条目排序：按发布时间从新到旧；发布时间解析不了的（例如 NIH 的 `11/05/2026 - 12:00`、两位年份的 `Thu, 05 Nov 26 …`），按收集任务第一次见到它的时间算；时间相同的按订阅源里的顺序。
- 取不在 `seen_items` 里的最新几条，条数等于这个订阅源的“每次篇数”。只处理这几条：有跳过的就少收，不再往下取，不用旧文章补数。
- 一条被跳过时也写进 `seen_items`，以后不再抓取。跳过的情况：字数不在上下限之内、正文提取不出来、抓原网页永久失败（除 408、429 以外的 4xx，超过大小，地址不允许）、和已有文章正文相同。
- 抓原网页临时失败（网络错误、超时、5xx、408、429）时这一条不写 `seen_items`，这次不收；以后的时间点它如果还在最新的几条里，会再试。

### 抓取的限制

读订阅源和抓原网页都遵守：

- 只用 https；
- 每个请求 10 秒超时；
- 响应体最多 2 MB，超过就中止；
- 最多 5 次重定向，每次重定向的目标重新检查全部限制；
- 按实际连接的 IP 检查，拒绝私有、回环、链路本地和其他非公网地址；
- User-Agent 固定为 `vexto/<版本> (+<仓库地址>)`，仓库地址取自配置。

### 整理一篇文章

1. 用 fast-xml-parser 解析 RSS 或 Atom。
2. 规范化原文地址（主机小写，去掉 fragment 和 `utm_*` 等跟踪参数，去掉末尾斜杠），算哈希，用于 `seen_items`。
3. 取正文：`feed` 用条目里的内容；`page` 抓取原网页，用 @mozilla/readability 在 jsdom 上提取，不执行网页里的脚本。需要登录或付费、正文靠脚本加载的网站可能抓不到。
4. 整理成干净的英文正文：去掉 HTML 标签、广告、脚本、导航、侧栏和评论，只保留标题和段落这类结构。规范正文里句子之间一个空格，段落之间两个 LF。
5. 用 `Intl.Segmenter`（英文，按句）切分句子，记下每句在正文里的起止位置和所在段落。
6. 数字数，不在上下限之内的跳过。
7. 算规范正文的哈希；已有相同正文的文章就跳过，挡住地址不同但正文相同的情况。
8. 写入 `articles`（`preparing`，`retry_at` 为现在）、`article_sentences` 和 `seen_items`，接着合成朗读。

文章内容只当数据处理，里面的任何指令都不执行。

### 合成和发布

1. 建这篇文章的音频行（`pending`，规则见“朗读和存储上限”）。
2. 用 Supertonic 3 的 F1 声音逐句合成；模型不输出时间戳，按每句音频的长度得出时间轴。
3. 拼成整篇，句子之间插入 300 毫秒静音（`config/speech.json` 的 `sentenceGapMs`）；静音不算进前后任何一句的起止时间，第一句之前和最后一句之后没有静音。用 lame 编码成单声道 MP3 32 kbps，ID3 注释写 `AI-generated voice (Supertonic 3)`，上传到音频行的对象键。
4. 在一个事务里把音频行标成 `ready`、写入每句的起止毫秒、把文章标成 `ready`：`collected_at` 设为这一刻，清空 `retry_at`。它就出现在列表里；推迟到下个月才合成的文章也按合成完的时间排在最前面。
5. 每篇文章的合成写一条用量记录（模型版本、CPU 时间、音频时长），并记进当月的合成用量。

### 失败和重试

- 文章开始合成前，`attempts` 加 1，`retry_at` 设为现在加上这一次的退避：第 1–4 次分别是 15、30、60、120 分钟（收集任务每 15 分钟一次，退避是它的倍数）。所以进程中途退出时，文章也会按时重试。因合成预算推迟的文章没有开始合成，不加 `attempts`。
- 合成失败时记下 `last_error_code`（取值见 `data.md`）；`attempts` 已经是 5 的标成 `failed`，否则等 `retry_at`。开始处理时 `attempts` 已经是 5 的 `preparing` 文章（上一次中途退出）也标成 `failed`。下次重试整篇重新合成，不做逐句的检查点。
- `failed` 的文章不再重试，也不出现在列表里。
- 收集失败不发通知，只写 Cloud Logging；日志里不写文章正文和查词内容。

### 保留期限

收集任务每次执行的最后删除过期的行：

| 数据                 | 保留                                                   |
| -------------------- | ------------------------------------------------------ |
| `failed` 的文章      | 写入后 30 天，连同句子                                 |
| `operation_receipts` | 24 小时                                                |
| `seen_items`         | 首次见到后 180 天（订阅源覆盖的时间窗口最长约 100 天） |
| `pending` 的音频行   | 建立后 1 小时，按淘汰的步骤删除（可能已经写了对象）    |

## 朗读和存储上限

- 文章、单词和例句的声音都是 Supertonic 3 的 F1，单声道 MP3 32 kbps。每个音频记录生成时的声音、模型版本和编码版本；换了声音或音质以后，只有新生成的音频用新版本，旧音频不重建。
- 读音的规范文字：NFC 规范化，去掉首尾空格，连续空白合并成一个空格，保留大小写。单词读音的文字是词条，例句读音的文字是例句。
- 模型的字符表里没有的字符，合成时直接去掉；文章、单词和例句都一样。
- `cache_key` 用来找已有的音频：单词和例句是“规范文字、声音、模型版本、编码版本”用换行连起来后的 SHA-256（十六进制），同一段文字不分单词和例句共用一个音频；文章是“`article`、文章 ID、声音、模型版本、编码版本”的 SHA-256。不是 `retiring` 的行里，`cache_key` 唯一。
- 对象键用音频行的 ID：单词和例句是 `speech/<音频 ID>.mp3`，文章是 `articles/<音频 ID>.mp3`。对象键不含原文，Spell 题的例句音频地址不透露例句文字；一个 `cache_key` 被淘汰后重新生成时用新的 ID 和新的对象键，删除旧对象不会删掉新的。
- 单词和例句的读音由 Cloud Run 服务 `vexto-tts` 当场合成。用户点播放时，Web 应用：
  1. 按 `cache_key` 找不是 `retiring` 的音频行；是 `ready` 就直接签发播放地址。
  2. 没有就插入一行 `pending`（新的 ID 和对象键），和别的请求同时插入时以先插入的那一行为准（`ON CONFLICT DO NOTHING` 后重读）。
  3. 行是 `pending` 时，用它的对象键同步调用 `vexto-tts`；成功后把行标成 `ready`，写入大小和时长，再签发播放地址。两个请求同时遇到同一个 `pending` 行时都会调用，最多浪费一次合成，写的是同一个对象。
  4. 调用失败时行留在 `pending`，下次点播放接着用它。
  5. 调用成功后行已经不是 `pending`：别的请求先把这一行标成了 `ready` 时，直接用它。行在合成期间过期、被收集任务淘汰时，淘汰删除对象可能早于朗读服务写入，所以这次请求删除自己刚写的对象，删除失败只记日志；这个 `cache_key` 有别的 `ready` 行时用那一行，没有时这次播放按朗读服务不可用处理。
- 读音不分用户，所有人共用。朗读服务用的是 Cloud Run 服务的免费额度，不计入收集任务的合成预算。
- 部署后的冒烟测试让 `vexto-tts` 写固定的对象键 `smoke/check.mp3`，每次覆盖；它没有音频行，不计入存储容量。
- 播放用预签名地址，10 分钟有效，过期时重新签发；音频不经过 Web 应用转发。
- 存储上限：容量上限写在配置里（5 GB）。容量按还有对象的音频行算，即 `ready` 和 `retiring` 的行的 `byte_size` 合计，`retiring` 的行在对象删掉之前一直计入。收集任务每次合成文章之前先估算这篇文章的音频大小：字数按每分钟 150 词折算成时长，加上句子之间的静音，按 32 kbps 换算成字节。合计达到上限的 95%，或者合计加上这篇的估算会超过 95%，就按 `created_at`、`id` 从早到晚把 `ready` 的音频标成 `retiring` 并删除，直到合计加上这篇的估算低于 90%；每批最多 50 个。文章音频连同文章一起删除，单词和例句的音频也在这里淘汰。播放不刷新时间，淘汰顺序只看创建时间。Web 应用写单词和例句音频时不检查容量。
- 被删除的单词或例句音频，下次有人点播放时重新生成。
- 结算保护停用 Google Cloud 结算后，新文章和单词、例句的读音不再生成，已有的文章和音频照常可用；点读音时显示 `Audio isn't available right now.`。

## 文章列表、搜索和播放

- 列表只显示 `ready` 的文章，默认按 Collected（文章可以阅读的时间）从新到旧。
- 排序字段：Collected、Last visited（当前用户的最近访问时间）、Article（标题，不分大小写）、Source（订阅源显示名）、Category（分类显示名）；升序或降序。Source 和 Category 按配置里显示名的字母顺序排，服务端把键换成它的名次再排。没访问过的文章在按 Last visited 排序时总在最后，倒序时也一样；值相同时按 ID 同方向排，顺序稳定。
- 筛选：Source 多选（之间是“或”）、Category 多选（之间是“或”），两种筛选和搜索之间是“且”。全部勾选等于不筛选。选项是配置里的全部订阅源和分类。
- 搜索：英文全文搜索，只查正文，不超过 200 字符；用 `plainto_tsquery('english', …)`（英文词干，词之间是“且”）；空白时不搜索；只有停用词时结果为空。搜索不改变用户选的排序。
- 分批加载：每批 20 条，用键集游标（排序值 + ID），每次查询算一遍总数；游标只对发出它的那个查询（排序、方向、搜索和筛选）有效。客户端按 ID 去重。已加载的批次和顺序一直保留，直到改变搜索、筛选或排序，或者重新载入页面；在那之前新收集的文章不插进来。进入阅读页记下访问后，只更新已加载的列表里那一篇的 Last visited。
- 访问记录：进入阅读页就记，一个用户一篇文章一行，用数据库时间，只增不减。
- 连续播放的队列在客户端：点 Play all 或某篇的播放键时，向服务端要一次当前查询（搜索、筛选、排序）的全部有序文章 ID，存在内存和 sessionStorage 里。Play all 从第一篇开始；某篇的播放键从那一篇开始，跳过它前面的。开始后出现的新文章不进入这次的队列；队列里已被淘汰的文章打开时返回 404，跳到下一篇。不承诺跨设备、刷新页面后接着播。
- 播放中从列表点卡片打开一篇文章（包括正在播的那篇）：停止播放，清空队列。
- 一篇播完：在前台先回到同一查询的列表（需要时加载到下一篇所在的那批），约 500 毫秒后打开下一篇，从第一句开始播；在后台和锁屏时只换音频，不切换页面，回到前台时直接显示正在播的那篇。最后一篇播完回到列表，停止播放。
- 没有队列时（在阅读页上直接播放），播到文末就回到未播放的状态，下次从第一句开始。
- 句子播放键只播这一句，播完停；再按一次停止并取消选中。选中一句后按顶部播放键，从这一句连续播到文末。
- 同一时间只有一个音频在播。打开查词浮窗不暂停文章；播放单词或例句的读音时暂停文章并记住位置，读音播完不自动恢复。进入复习时暂停文章，结束复习不恢复。
- 播放速度存在设备的 localStorage 里，换文章、刷新页面和退出登录后保留。
- 第一次连续播放需要用户的点按；浏览器拦下自动播放（例如后台跨篇、预签名地址续签后）时，播放器显示 Tap to continue。
- 锁屏控制用 Media Session：标题是文章标题，副标题是来源名称，专辑是 vexto；有播放、暂停和下一篇（只在有队列时）。

## AI 查词

### 选区和上下文

- 可以点一个词，也可以长按并拖动选择手柄选一段，可以跨视觉行、跨相邻的句子；拖选结束才发请求。
- 文章、浮窗例句、词卡详情的例句和复习题面都可以查词。
- 一次最多 8 个词或 80 个字符，这是选区唯一的限制；超过时提示 `Select up to 8 words.`，不发请求；服务端同样检查，超过返回 422。
- 上下文：文章里是选区碰到的那几句（最多 8 句），例句里是整条例句。客户端只传上下文的定位（哪篇文章的第几句到第几句、哪条例句）和选区在上下文里的位置；服务端按定位重建上下文文字，不接受客户端传来的原文。定位的字段见 `interfaces.md`。
- Spell 题的选区不能和挖空的目标词重叠，重叠时提示 `Select words on one side of the blank.`，接口返回 422 `HIDDEN_RANGE`。

### 输出

一次模型调用返回：

| 输出       | 要求                                                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 词条       | 选区的原形（lemma）                                                                                                                       |
| 词性       | 固定英文列表之一：noun、verb、adjective、adverb、preposition、conjunction、pronoun、determiner、interjection、phrase、phrasal verb、idiom |
| 中文释义   | 这个词在这句话里的意思，最多 30 个字符（含标点），可以用分号写两个近义的说法                                                              |
| 例句       | 2 条新造的英文句子，每条 8–20 词，难度和原文相近，目标词按原文的形式或常见变形出现；不给中文翻译                                          |
| 可接受词形 | Spell 判定时接受的词形，包含词条本身                                                                                                      |

- 输出先用 Zod 校验格式，再检查含义：服务端在每条例句里按可接受词形（不分大小写、整词匹配）找出目标词的位置，作为 `target_ranges`；找不到、词数不对或词形不合理时算不合格。模型不给位置。
- `lemma_key` 是词条做 NFC 规范化、转小写、去掉首尾空格、合并连续空白、弯撇号换成直撇号后的结果，用于找同一词条的词卡。
- 每次模型调用 15 秒超时。交互式调用最多重试一次临时错误（超时、连接中断、429、5xx），外加一次语义修复（把不合格的答案和原因交给模型重做）；每次调用都写用量记录。都用完仍失败时接口返回 503 `UNAVAILABLE`，什么都不保存。
- 模型没有任何工具；文章和例句的内容只当数据，里面的指令一律不执行。

### 缓存

- 键是“用户 + 规范化上下文的哈希 + 选区”，不含文章和来源；不同文章里同一句话的同一选区共用结果；哈希相同时仍核对原文。规范化只把连续的空白合并成一个空格，选区的位置跟着移动；不做 NFC 规范化。
- 命中缓存时不调用模型。
- 返回查词结果时，如果用户已经有从这个查词结果存下的词卡，一起返回那张卡的 ID，浮窗显示已保存。
- 页面重新获得焦点、网络恢复时的自动重新获取不调用模型；查词、刷新例句和保存都要用户明确操作。

### 刷新例句

- 只替换当前显示的这一条（同一个位置，新的 ID），词义不变；失败时保留原来的例句。
- 新例句和同组里已有的一条相同时算不合格，重新生成；最多试 2 次，仍相同就算刷新失败。
- 例句的条数只由第一次查词决定，刷新不会追加。
- 查词结果的例句和词卡的例句各自刷新，互不影响。查词结果的例句刷新时，模型看到的上下文是查词时的上下文；词卡没有查词的上下文，刷新词卡的例句时用被换掉的那条例句。

## 生词本

### 保存

1. 点浮窗的加号保存最上层的查词结果。
2. 用户已经有从这个查词结果存下的词卡时，不调用模型，直接返回 409 `DUPLICATE_WORD` 和那张卡，界面同样显示替换对话框。
3. 否则找这个用户 `lemma_key` 和词性都相同的词卡；词性不同就是不同的意思。有这样的卡时调一次模型（用量种类 `meaning_match`），判断这次的意思和其中哪一张是同一个；是同一个就返回 409 `DUPLICATE_WORD` 和那张卡的中文、例句和 `updatedAt`，界面显示替换对话框。
4. 不是同一个意思时，调模型生成 Translate 的三个干扰项：和正确项同词性、意思明显不同、长度相近，不能是近义词，也不能是这个词的其他义项。服务端检查：恰好三个；每个都符合中文释义的要求（含汉字，最多 30 个字符）；去掉空格和标点后，不等于正确释义，也不等于正确释义用 `；;，,、` 分开的任何一个说法，所以正确选项恰好一个；三个互不相同；长度（按码点）至少是正确释义的三分之一，至多是“正确释义加 6”和“正确释义的两倍”中较大的那个。选项顺序在保存时随机定下，以后不变。
5. 在一个事务里先锁住这个用户的 `members` 行（`SELECT … FOR UPDATE`），让同一用户的保存、替换和删除依次进行；复查同词条、同词性的词卡和第 3 步看到的一样，再建词卡（记下来源的查词结果）、复制整组例句、建四个选项和三行复习进度（`round = 0`，`due_at` 为空）。复查不一致时从第 2 步重做一次，仍不一致返回 409 `CONFLICT`。
6. 模型调用都在事务之外。四个选项都通过校验才保存，否则整个保存失败。

### 替换

- 替换对话框左右对比已存的和这次的中文与例句。对话框里已存的内容可能已经过时，这是允许的。
- 替换请求带上 `DUPLICATE_WORD` 返回的那张卡的 `updatedAt`。服务端先在事务外重新生成四个选项，再在一个事务里（同样先锁 `members` 行）重读词卡：卡已删除返回 404，`updatedAt` 不一致返回 409 `CONFLICT`；一致时更新中文释义、例句、可接受词形和来源的查词结果，写入新选项。任何一步失败，整个替换不做。
- 查词结果的词条和词性要和词卡相同，否则返回 422。
- 三种模式的复习进度保持不变。

### 删除

- 单个删除和批量删除用同一个确认框。批量删除每次 1–100 个不同的词，在一个事务里删除；所选的词里有任何一个已经不存在，整批不删，返回 409 `SELECTION_CHANGED`。不接受按条件删除。
- 删除一张词卡时删除它的例句、选项和三行进度；查词缓存保留。

### 列表

- 状态标签：All、New（三种模式都没答过）、Ongoing、Archived（三种模式都完成）。状态由复习进度派生。#3 不出 Speak 的题，Speak 不能完成，所以 Archived 一直为空。
- 搜索：不超过 100 字符，提交时去掉首尾空格。词条、中文释义、词性和词卡的例句里含有搜索文字（不分大小写的子串，绑定参数的 `ILIKE`，转义 `%` 和 `_`），或者例句和搜索文字的英文全文搜索相符（`plainto_tsquery('english', …)`，能找到变形），就算符合。
- 轮次筛选：每种模式多选 Round 1–7 和 Complete；同一模式之内是“或”，模式之间是“且”。Round n 指下一次要答的轮次，即 `round = n − 1`；Complete 是 `round = 7`。
- 排序：Word（默认，按 `lemma_key` A–Z），以及每种模式的 Round 和 Next，共 7 个字段。Next 按实际的到期时间排；新词和已完成的没有到期时间，总排在最后，倒序时也一样。值相同时按 `lemma_key`、再按 ID 排。
- 分批加载，每批 20 条，用键集游标。

## 间隔复习

三种模式（Speak、Spell、Translate）各自独立排期。#3 不做 Speak 的题面、录音和判定，但每张词卡照样建 Speak 的进度行。

### 轮次和间隔

| 事件                                                           | 效果                                                           |
| -------------------------------------------------------------- | -------------------------------------------------------------- |
| 答对                                                           | 轮次加 1；到第 1、2、3、4、5、6 轮分别等 1、2、4、7、15、30 天 |
| 答对后到第 7 轮                                                | 这种模式完成，`due_at` 为空，不再出题                          |
| 答错                                                           | 轮次减 1（最低 0），10 分钟后再出                              |
| 技术失败、没提交、结果未知                                     | 不变                                                           |
| 提交还没到期或已完成的题                                       | 409 `CONFLICT`，不改动                                         |
| Translate 选的选项不在这张卡现有的选项里（出题后词卡被替换过） | 409 `CONFLICT`，不改动                                         |

- 一天是 24 小时，不按日历日。时间取最终提交事务里的数据库时间。
- 三种模式都到第 7 轮，词卡才归档（Archived）；归档不另外记录，由列表按三行进度派生，复习时不为归档写任何东西。#3 里 Speak 不出题、不能完成，所以 Archived 一定是空的。

### 出题

- 每次现场查询：先出到期的（按 `due_at`、卡片 ID 从早到晚），再出新词（按卡片的创建时间、ID）。没有学习会话，没有每日上限；刚保存的词和刚到期的题下一次查询就能出现。
- 没有可出的题时返回空，并给出这种模式下一次到期的时间。

### Spell

- 题面：中文释义、词性、挖空的例句（所有例句都挖空，不只当前那条），以及播放当前例句完整读音（含目标词）的 Play example。中文、词性和挖空例句是提示。
- 挖空的位置：存下的目标词位置，加上例句里出现的任何一个可接受词形（整词、不分大小写、弯撇号和直撇号都算），重叠的合并。所以例句里每一处可接受词形都被挖掉。
- 作答前，目标词和它的所有变形不出现在接口数据、页面元素、可访问名称、提示文字和音频地址里；音频地址用不透露文字的对象键。
- 判定：答案做 NFC 规范化、去掉首尾空格、合并连续空格、不区分大小写、弯撇号换成直撇号，和同样处理过的可接受词形逐个精确比较，不算编辑距离。答案不超过 80 字符。

### Translate

- 题面：英文词条、词性、不挖空的例句和四个中文选项（每个选项带词性）。正确选项的 ID 不发给浏览器。
- 判定：选中的选项 ID 等于正确选项。

### 计数

- Vocabulary 导航和模式按钮上的红色数字是到期的题数，黄色数字是新词的题数；每种模式分别计数，导航上是各模式相加。数字不受列表的筛选影响，0 时不显示。
- #3 的计数不含 Speak，导航上是 Spell 和 Translate 相加。
- 计数跟着进度随时更新：提交答案后（有了结果，或者返回 409、404），客户端马上重新读取计数。答过的题不再到期（答对的按轮次等几天，答错的 10 分钟后才再到期），所以它的数字随即减少：到期的题减红色数字，新词减黄色数字。保存、替换和删除词卡后，以及页面重新获得焦点时，也重新读取。

## 并发和多设备

- 去重回执：带 `operationId` 的写操作（哪些接口带见 `interfaces.md`），服务端在写入的同一个事务里按所有者和 `operationId` 记下操作类型、请求摘要和响应，保留 24 小时。同一个 `operationId`、同样的操作类型和请求再来一次，返回第一次的响应，不重复写入；操作类型或请求内容不同返回 409 `OPERATION_MISMATCH`。同一个 `operationId` 的两个请求同时到达时，后一个等前一个的事务结束再读回执。没有查询操作状态的接口：响应丢失时，用同一个 `operationId` 重发请求就是核对的方式。
- 用户改了内容再提交（例如改了 Spell 的答案）是新的操作，用新的 `operationId`；原样重试才用原来的。
- 刷新、替换和删除不传版本号，替换只带 `DUPLICATE_WORD` 给出的 `updatedAt`；服务端在短事务里加锁重读，状态变了就返回 409，不用 upsert。删除之后迟到的请求不会把行重新建出来；迟到的刷新只更新仍然存在、意思没变的行。
- 复习：提交时锁住那一行复习进度复查是否到期。两个不同的 `operationId` 紧接着提交同一张卡的同一种模式，先到的把到期时间推到将来，后到的得到 409，轮次不会重复加减。
- 客户端收到 `CONFLICT` 时重新读取数据，不静默覆盖；`DUPLICATE_WORD` 打开替换对话框，`SELECTION_CHANGED` 刷新所选的词。每种错误在界面上的显示见 `screens.md` 的“错误的显示”。
- 多设备之间的变化在切换页面、取下一题、提交和窗口重新获得焦点时核对，不用 WebSocket。
- AI、语音合成和对象存储的调用不放在数据库事务里，提交前再检查一次状态。

## 错误和断网

- 应用不支持离线使用，查词、读音和复习都要联网。
- 断网时写操作不排队，并保留用户的输入。
- 只在具体的故障发生时显示错误和重试按钮，不放常驻的技术说明。界面上的位置和文字见 `screens.md`，错误代码见 `interfaces.md`。
- 会话的续期：Clerk 在浏览器里续期一分钟有效的会话令牌。手机从休眠或后台回来时，页面重新获得焦点就会重新读取数据，这些请求可能赶在 Clerk 续期之前带着过期的令牌到达，接口返回 401。所以收到 401 时，客户端先请 Clerk 不用缓存地取一个新令牌，同一时刻被拒的请求共用这一次：
  - 取到了，会话还在：被拒的读取原样再发一次，同一个读取一分钟内最多再发一次。被拒的写操作不重发，这次操作算失败，显示和这个操作的 `INTERNAL` 一样，但不带 Retry，用户可以再做一次。取播放地址（`POST /api/media/playback`）不改数据，算读取。
  - 取不到，或者同一个读取一分钟内再次被拒：打开登录页，被拒的操作自己不显示失败。
- 收到 403 `NOT_A_MEMBER` 或 `TERMS_REQUIRED` 时，客户端重新读取自己的资料，页面随之换成没有资格页或条款页；读取和写操作都这样处理，被拒的操作自己不显示失败。
- 朗读服务不可用（包括结算保护停用了结算）时，单词和例句的读音显示 `Audio isn't available right now.` 和 Retry；文章照常阅读和播放。

## 通知

- 没有推送和邮件通知，收集失败和合成预算用完也不通知，只写日志。
- 应用里只有两种提醒：Vocabulary 导航和模式按钮上的红、黄数字；操作结果的短提示。文字见 `screens.md`。

## 用量记录

- 每次实际调用 AI 或语音合成，都在调用前写一条 `pending` 的用量记录，调用后补上服务商的请求 ID、用量、状态和价格版本；未知的用量留空，不当作 0。
- 状态：
  - `unknown`：调用可能已经做完了但不知道结果。AI 是超时或连接中断；朗读服务是超时或返回的内容读不懂。
  - `failed`：AI 返回了错误状态（`error_code` 是 `http_<状态>`），或者回答没通过检查（`invalid_output`，记下这次的 token 和金额）；朗读服务拒绝了请求、连不上，或者取不到调用它的身份令牌。
- 金额是十进制的估算值，按价格表计算。价格表随版本发布（`config/prices.json`），有版本号，每个模型一项；AI 的输入 token 都按完整的输入价计算（缓存的输入更便宜，所以是上限）；Supertonic 3 在 Cloud Run 的免费额度里，按 0 计。用量未知时不写金额和价格版本。
- 记录的种类和涉及的资源（`resource_type`）：

| 种类            | 什么调用                   | 资源                                         |
| --------------- | -------------------------- | -------------------------------------------- |
| `lookup`        | 查词                       | 无（查词结果还没建）                         |
| `meaning_match` | 保存时判断是不是同一个意思 | `lookup`：这次的查词结果                     |
| `example`       | 刷新例句                   | `lookup` 或 `card`：例句所在的查词结果或词卡 |
| `translation`   | 生成 Translate 选项        | 保存时是 `lookup`，替换时是 `card`           |
| `article_tts`   | 文章朗读                   | `article`                                    |
| `word_tts`      | 单词读音                   | `audio`：写入的音频行                        |
| `example_tts`   | 例句读音                   | `audio`：写入的音频行                        |

- 文章朗读由收集任务记录，`owner_id` 为空；其余记录当时的用户。

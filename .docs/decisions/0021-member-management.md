# 0021 管理成员名单的命令

## 背景

只有受邀的人能用 vexto。名单存在每个目标数据库的成员表里，由项目所有者用 `task member` 增加、取消和列出。命令要连上目标环境的数据库，但连接地址只存在 GitHub 环境的密钥和 Vercel 的 Sensitive 变量里，两处都读不出来。仓库是公开的。

## 比较过的方案

- 手动启动的 GitHub 工作流，用目标环境的密钥连数据库。
- 项目所有者每次从 Neon 网页复制地址，写进不提交的 `secrets.local.env`，命令读完就删。
- 命令用 Neon CLI（`neonctl`）按目标的 Neon 项目和分支取连接地址，直接在内存里交给脚本。

## 决定

`task member` 用 Neon CLI 取连接地址。Neon CLI 用 `pnpm dlx` 临时运行，版本写死在 `Taskfile.yml` 里；每个目标的 Neon 项目和分支写在配置里；项目所有者事先在本机用 Neon CLI 登录一次。地址不显示，也不写进文件。

## 理由

- 公开仓库的工作流运行日志和手动输入谁都能看，用工作流会暴露成员的邮箱。
- 地址从 Neon 直接到脚本，不经过人手和文件，符合密钥不进命令行、不显示的规则。
- 不需要额外保存一份数据库地址。

## 代价

- 项目所有者的电脑上要能运行 Neon CLI，并保持登录。
- 只有能登录 Neon 组织的人能管理名单。

## 何时重新考虑

成员多到需要在应用里管理，或者仓库改成私有时。
